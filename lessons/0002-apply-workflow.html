Workflow Apply: từ nút bấm đến Supabase

Toàn cảnh luồng Apply

1
Presentation — Page
Seeker mở JobDetailPage → bấm "Ứng tuyển" → navigate đến ApplyPage
lib/features/jobs/presentation/pages/job_detail_page.dart
lib/features/application/presentation/pages/apply_page.dart

Presentation — Provider
ApplyPage gọi ref.read(applicationProvider.notifier).apply(...)
lib/features/application/presentation/providers/application_provider.dart
3
Domain — UseCase
Provider gọi ApplyJobUseCase (có UseCase vì apply = nhiều bước: validate resume, insert application)
lib/features/application/domain/usecases/apply_job_usecase.dart
4
Domain — Repository (abstract)
UseCase gọi ApplicationRepository.applyToJob() — chỉ biết interface, không biết Supabase
lib/features/application/domain/repositories/application_repository.dart
5
Data — Repository impl + Datasource
Repository impl gọi ApplicationDatasource.applyToJob() → INSERT vào bảng applications với status = 'pending'
lib/features/application/data/datasources/application_datasource.dart
6
Backend — Supabase
Supabase kiểm tra RLS (Seeker chỉ insert được Application của chính mình) → ghi vào PostgreSQL

Vòng đời Application (status flow)

pending  →  Shortlist (reviewing)  →  Invite (interview)  →  Hire (accepted) / Reject (rejected)

pending  →  Withdraw (withdrawn) — chỉ Seeker, chỉ khi còn pending

Recruiter dùng ApplicantsPage → bấm action → gọi Supabase RPC update_application_with_note hoặc update_application_with_interview (atomic — update status + insert note/schedule trong 1 transaction).

Tại sao Withdraw chỉ được khi pending?

Datasource kiểm tra bằng .eq('status', 'pending') trong WHERE clause:

await _supabase
  .from('applications')
  .update({'status': 'withdrawn'})
  .eq('seeker_id', seekerId)
  .eq('id', applicationId)
  .eq('status', 'pending')   // ← nếu không còn pending → 0 rows → Left(Failure)
  .select();

Nếu result rỗng → trả Left(DatabaseFailure). UI hiện thông báo lỗi.
