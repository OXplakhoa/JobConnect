Clean Architecture trong JobConnect

Hiểu cấu trúc 3 tầng để giải thích cho cô bất kỳ chức năng nào

Tại sao Clean Architecture?

Cô hỏi: "Em tổ chức code thế nào?" — đây là câu bạn phải trả lời được mà không nhìn màn hình. Clean Architecture chia code thành 3 tầng, mỗi tầng chỉ biết về tầng bên trong nó.

Presentation → Domain → Data ───────────── ──────────────── ────────────── Widget Entity Datasource Provider/Notifier UseCase Repository (impl) Repository (abstract) Failure features/xxx/ features/xxx/ features/xxx/ presentation/ domain/ data/ pages/ entities/ datasources/ widgets/ usecases/ models/ providers/ repositories/ repositories/

Quy tắc phụ thuộc

Presentation gọi Domain — OK
Domain gọi Data — KHÔNG BAO GIỜ
Domain không biết Supabase tồn tại
Data không import Flutter Widget

Kết quả: nếu mai mốt đổi Supabase sang Firebase, chỉ cần viết lại XxxRepositoryImpl và XxxDatasource — không đụng đến business logic hay UI.

Chi tiết từng tầng

1. Data Layer — "Nói chuyện với Supabase"

Datasource (xxx_datasource.dart): class duy nhất được gọi Supabase trực tiếp.

// Ví dụ: application_datasource.dart
Future<Either<Failure, void>> applyToJob({...}) async {
  try {
    await _supabase.from('applications').insert({...});
    return const Right(null);
  } on PostgrestException catch (e) {
    return Left(ApplicationErrorMapper.fromPostgrest(e));
  }
}

Model (xxx_model.dart): Freezed class biết JSON. Có fromJson/toJson.

Repository impl: nhận Datasource, trả Either<Failure, T> lên tầng Domain.

2. Domain Layer — "Business logic thuần Dart"

Entity: pure Dart class, không có annotation JSON, không biết Supabase.

Repository (abstract): interface khai báo contract — ví dụ applyToJob(). Domain gọi interface này, không biết impl.

UseCase: 1 class = 1 hành động. Ví dụ ApplyJobUseCase có method call().

Quy tắc UseCase: bắt buộc khi có nhiều bước / cross-cutting concerns. Được bỏ qua khi là CRUD đơn giản — provider gọi repository trực tiếp.

3. Presentation Layer — "UI + State"

Provider: @riverpod annotation, expose state cho Widget. Luôn ref.watch(authProvider) để auto-rebuild khi login/logout.

Page: Widget full-screen, là route destination.

Widget/Card: component nhỏ hơn, tái dụng trong nhiều page.

Either<Failure, T> — không throw exception

Repository không bao giờ throw. Thay vào đó trả về:

Right(data)    // thành công
Left(failure)  // lỗi — NetworkFailure, DatabaseFailure, AuthFailure...

UI dùng .fold():

result.fold(
  (failure) => showError(failure.message),
  (data)    => showData(data),
);
Tại sao không throw? Exception có thể bị miss, stack trace rất dài, khó test. Either buộc caller phải handle cả hai case — compiler enforce.
